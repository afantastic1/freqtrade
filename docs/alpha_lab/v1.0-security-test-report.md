# Alpha Lab v1.0 Candidate Isolation Report

Date: 2026-10-19. Host: WSL Linux 7.0.0-34-generic. Bubblewrap: `/usr/bin/bwrap`.

The host can create a user, PID, IPC, and UTS isolated Bubblewrap process with read only `/usr`, `/bin`, `/lib`, and `/lib64`. The proof command exited 0.

The required network namespace cannot be created inside the current managed workspace. `bwrap --unshare-net ...` failed before candidate execution with `Failed to create NETLINK_ROUTE socket: Operation not permitted`. This is an outer sandbox restriction and prevents an end to end proof of the required target WSL isolation boundary in this session.

No prompt or OpenCode permission is accepted as a substitute. Because the repository currently imports candidate `factor.py` in the trusted Python process, attempts to write `runner.py` or SQLite, read private files, spawn commands, and connect to the network are not reliably contained. Malicious candidate acceptance therefore fails.

Disposition: unattended execution of untrusted candidate Python is prohibited. Alpha Lab remains `1.0.0-rc1`; the v1.0 freeze and release recommendation are blocked until a dedicated Bubblewrap worker is implemented and the five malicious operations are observed failing on the actual target WSL host. Existing candidates may only be run after maintainer review in a disposable credential free environment.

Required retest commands must exercise a real candidate through the public CLI, not source inspection: overwrite engine file, overwrite a copied SQLite file, read a canary private file, execute `/bin/sh`, and connect to a local listening socket. Each must fail while a benign candidate succeeds and the trusted parent alone writes results.
