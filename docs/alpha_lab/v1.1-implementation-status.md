## Data and CLI

The installed `user_data/data/binance/futures` directory currently has BTC and ETH perpetual OHLCV files at supported periods; five-asset statistical cross-sectional acceptance needs more historical contracts. The construction tests use deterministic synthetic panels and do not read 2025+ data. The preparation adapter wraps Freqtrade's existing Futures Feather loader and writes a bounded CSV plus `.quality.json`; it does not download data or fill missing bars. **Do not run it on a Feather source that may contain reserved 2025+ rows during this acceptance:** the underlying loader can read the full file before applying the date filter.

Maintainer preparation command for a *verified bounded source*:

```bash
.venv/bin/python -m alpha_lab.panel_cli --symbol BTC/USDT:USDT --symbol ETH/USDT:USDT --timeframe 1h --datadir user_data/data/binance --start 2022-01-01 --end 2025-01-01 --output user_data/research/alpha_lab/panels/usdm_1h_2022_2024.csv
```

For legacy `time_series`, read historical results with `.venv/bin/python -m alpha_lab.research_cli list --json`; the old `candidate_cli run` remains an **unsafe Maintainer-only manual command** until candidate process isolation is proven. For cross-sectional work, copy [`cross-sectional-example.json`](cross-sectional-example.json) to `user_data/research/alpha_lab/candidates/current/config.json`, set `request.json` to `{"action":"cross_sectional_run","panel_id":"usdm_1h_2022_2024"}`, then invoke exactly:

```bash
.venv/bin/python -m alpha_lab.research_agent_cli
```

The same gateway supports `history`, `show` with a 32-hex run ID, `family_review`, and `decide` with a completed run and its exact 64-hex source hash. See the [draft protocol](research-protocol-v1.1-draft.md) for fields and interpretation. Direct Maintainer invocation of `cross_sectional_cli --config ... --panel-csv ...` is also available; the restricted Agent uses the no-argument gateway.

## Maintainer change procedure

Create a separate Maintainer change, record the protocol and method version, write a failing regression/Golden case, implement the fix, run full Alpha Lab and SQLite checks, run adversarial security tests when candidate access changes, compare Golden output before and after, review the complete diff, then update the new frozen manifest and require CODEOWNER review on a protected branch. Never edit old Evidence or repurpose an existing method version.
