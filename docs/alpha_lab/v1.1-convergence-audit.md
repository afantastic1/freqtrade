## Frozen core and policy review

The v1.1 freeze covers the data, labels, evaluation, models, statistics, validation and factor modules, their tests, experiment identity and store, selected CLIs, version metadata, Agent prompt/skill, CODEOWNERS, freeze workflow, and statistical freeze notes. The verifier compares recorded SHA-256 values and metadata and detects newly added frozen files. Its current successful result establishes integrity against the checked-in v1.1 manifest, not a release approval or successful inference calibration.

The gateway accepts fixed actions and fixed engine-owned transforms; it does not accept a candidate Python factor. Its code checks request shape, date window before panel load, panel path containment/symlinks, and redacts public errors. These are application-level checks. The `.opencode` ordered deny/allow rules and tests are not substitutes for a process sandbox. Do not advertise arbitrary Python execution as safe. Research Agents must not edit the protected core listed above. Any necessary core change requires a separate `ENGINE_CHANGE_REQUEST` for Maintainer review; no such request was implemented in this audit.

## Decision

The current HEAD has a reproducible 324-test result and a valid v1.1 manifest, but those do not close the independent data isolation, runtime/OS security, calibrated inference, and same-HEAD end-to-end gates. The release remains **`RC_BLOCKED`**. Minimum unblock scope is recorded in [acceptance report](v1.1-acceptance-report.md) and [known limitations](v1.1-known-limitations.md). No additional engine refactor is authorized by this audit.
