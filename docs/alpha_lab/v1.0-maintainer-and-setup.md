# Alpha Lab v1.0 Maintainer and Repository Setup

OpenCode v2.0.29 permission rules use last matching rule wins. The Alpha Researcher starts with default deny, then permits candidate writes and exact public CLI prefixes. These controls are defense in depth; they do not sandbox candidate Python.

An administrator must protect `my_dev` and release branches, require pull requests, disable force push/deletion, require the Alpha Lab workflow, require Alpha Lab CODEOWNER approval, restrict workflow bypass and `alpha-lab-v*` tags, and run the Research Agent without Git, exchange, or cloud credentials.

Maintainer changes start with a failing test, bump semantic versions when definitions change, record Golden differences, regenerate the freeze manifest, and run compilation, full tests, SQLite integrity/concurrency, sandbox abuse, Golden, and smoke checks before review.

Until sandbox abuse tests pass on the target WSL host, unattended arbitrary candidate Python execution is disabled and Alpha Lab must remain a release candidate.
